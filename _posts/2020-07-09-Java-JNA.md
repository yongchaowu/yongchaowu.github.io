使用JNA的过程中也不一定会一帆风顺,比如会抛出”非法内存访问”,这时候检查一下变量是否==null。
还有内存对齐的问题，当从内存进行保存的时候，如果内存对齐处理不好,就会抛出很严重的异常,导致JVM异常退出，JNA提供了四种内存对齐的方式，分别 是：ALIGN_DEFAULT、ALIGN_NONE、ALIGN_GNUC和ALIGN_MSVC。
- ALIGN_DEFAULT采用平台默认的对齐方 式(推荐);
- ALIGN_NONE是不采用对齐方式；
- ALIGN_GNUC为针对linux/gcc操作系统的对齐方式。
- ALIGN_MSVC为针对 win32/msvc架构的内存对齐方式。

<!--more-->

JNA 的 protected mode 默认关闭（以 JNA 5.3.1 和 5.19.1 源码为准）。如果使用系统属性，应在 JNA 类首次加载前设置 `System.setProperty("jna.protected", "true")`；也可以在初始化后调用 `Native.setProtected(true)`，再用 `Native.isProtected()` 检查底层平台是否真正支持。JNA 官方建议此模式仅用于测试/调试，不能把它当作防止 JVM 异常退出或非法内存访问的可靠保障。

```language
构造函数:
	public  NotesFileObjectStruct()  {
		super();
		setAlignType(Structure.ALIGN_NONE);
	}
```
