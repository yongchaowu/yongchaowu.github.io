## CPU
查看CPU详细信息：    `$cat /proc/cpuinfo`

<!--more-->

> **适用范围：** `/proc/cpuinfo` 的字段随 CPU/系统架构和内核而异。下面的 `physical id`、`siblings` 和 `cpu cores` 说明只适用于实际输出这些字段的 x86 系统，不能把乘法公式当作所有 Linux 架构的通用结论；需要跨架构的 CPU、线程、核心或插槽信息时，优先使用 `lscpu`。

```
CPU

    ①物理CPU数（physical id）：若该字段存在，可统计不同的 physical id。
    ②CPU核心数（cpu cores）：若该字段存在，表示处理器拓扑中的物理核心数。
    ③逻辑CPU数：可以直接统计 processor 条目；在提供上述字段的 x86 系统中，处理器、核心和线程的数量关系取决于实际拓扑。

    这些字段不是所有架构都提供，不能把上面的乘法公式当成跨架构通用公式；需要 socket/core/thread 拓扑时使用 lscpu。
```

```
processor:系统中逻辑处理核心数的编号，从0开始排序
vendor_id:CPU制造商
cpu family:CPU产品系列代号
model:CPU属于其系列中的哪一代的代号
model name:CPU属于的名字及其编号、标称主频
stepping:CPU属于制作更新版本
cpu MHz:CPU的实际使用主频
cache size:CPU二级缓存大小
physical id:单个物理CPU的标号
siblings:单个物理CPU的逻辑CPU数。如果cpu cores数量和siblings数量一致，则没有启用超线程，否则超线程被启用
core id:当前物理核在其所处CPU中的编号，这个编号不一定连续
cpu cores:该逻辑核所处CPU的物理核数。比如此处cpu cores 是4个，那么对应core id 可能是 1、3、4、5
apicid:用来区分不同逻辑核的编号，系统中每个逻辑核的此编号必然不同，此编号不一定连续
fpu:是否具有浮点运算单元（Floating Point Unit）
fpu_exception:是否支持浮点计算异常
cpuid level:执行cpuid指令前，eax寄存器中的值，根据不同的值cpuid指令会返回不同的内容
wp:表明当前CPU是否在内核态支持对用户空间的写保护（Write Protection）
flags:当前CPU支持的功能
bogomips:在系统内核启动时粗略测算的CPU速度（Million Instructions Per Second
clflush size:每次刷新缓存的大小单位
cache_alignment:缓存地址对齐单位
address sizes:可访问地址空间位数
power management:对能源管理的支持
```

```
以下命令仅适用于输出上述字段的系统；跨架构查询拓扑时优先使用 lscpu。

①查询系统物理CPU个数：
    $cat /proc/cpuinfo | grep "physical id" |sort |uniq
②查询系统逻辑CPU个数：
    $cat /proc/cpuinfo | grep "processor" | wc -l
③查询系统每个物理CPU的核数：
    $cat /proc/cpuinfo | grep "cpu cores" | uniq
④查询系统的每颗物理CPU核心是否启用超线程技术。如果启用此技术那么每个物理核心又可分为两个逻辑处理器：
    $cat /proc/cpuinfo | grep -e "cpu cores" -e "siblings" | sort | uniq
```

本文修订依据：Linux man-pages 6.19 [`proc_cpuinfo(5)`](https://man7.org/linux/man-pages/man5/proc_cpuinfo.5.html)、[`lscpu(1)`](https://man7.org/linux/man-pages/man1/lscpu.1.html)，以及 Linux v6.12 的 x86 [`proc.c`](https://github.com/torvalds/linux/blob/v6.12/arch/x86/kernel/cpu/proc.c)。`proc_cpuinfo(5)` 明确说明字段随架构而异；v6.12 的 x86 实现仅用于说明这些字段出现在 x86 拓扑输出中。
